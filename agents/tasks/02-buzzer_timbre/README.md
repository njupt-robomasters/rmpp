# 蜂鸣器音色模拟

目标：用 Python 模拟无源蜂鸣器的几种发声方案，先试听再决定是否改固件

## 复现

```sh
python -I agents/tasks/02-buzzer_timbre/simulate.py --raw
# 只输出一段，调参对比
python -I agents/tasks/02-buzzer_timbre/simulate.py --start 30 --seconds 20 --mix-gain 0.6 --slot 0.02
```

默认 MIDI 为 `reference/midi/always_with_me.mid`，输出到 `out/`（不入库），全曲约 20 s。依赖 `mido`、`numpy`、`scipy`，单音转换直接复用 `tools/midi_to_music.py`

## 输出

| 文件 | 方案 | 引脚波形 |
| --- | --- | --- |
| `0_baseline` | 现有播放器 | 单音抢占，固定 50% 方波 |
| `1_envelope` | 占空比包络 | 同上，每 1 ms 更新占空比，使基波幅度按 `exp(-t/tau)` 衰减 |
| `2_arpeggio` | 快速琶音 | 每 `slot` 在当前最高的 3 个音间轮换，叠加各音自己的包络 |
| `3_pwm_dac` | PWM-DAC 合成 | 4 声部加法合成钢琴音，32 kHz 量化为 1000 级 CCR，零阶保持 |
| `4_soft` | 改进占空比包络 | 右手旋律单音；衰减时间随音高变化，衰减到余音底后保持 |
| `5_soft_up12` | 同上升八度 | 靠近谐振峰 |
| `6_dac_mono` | PWM-DAC 单音方波 | 与 4 相同包络，但用幅度而非占空比实现，音色不随衰减变化 |
| `7_dac_duo` | PWM-DAC 2 声部方波 | 旋律 + 左手最低音升八度，各占一半幅度 |
| `7b_bass_decay` | 7 改进 | 低音衰减更快（A4 处 0.4 s）、余音底 0.12，松开 30 ms 淡出 |
| `7c_melody_lead` | 7b 旋律优先 | 旋律 0.6、伴奏 0.4 |
| `7d_up12` | 7b 升八度 | 两声部同时升八度 |
| `8_accent` | 起音插入低音 | 4 的基础上，低音每次起音插入 25 ms |

- 不带后缀：经过蜂鸣器模型，接近板上实际听感
- `_raw`：引脚理想电平（去直流），用于听方案本身
- 同组文件共用一个增益，保留方案间的响度差；脚本打印各文件相对基线的 RMS

## 模型与假设

- 蜂鸣器频响为粗略假设：300 Hz 二阶高通 + 4 kHz、Q 3、+18 dB 谐振峰 + 10 kHz 低通，可用 `--f0 --q --peak-db` 调整；未用实物测量校准
- 方案 1/2 的占空比到幅度按基波 `∝ sin(π·duty)` 反算，谐波成分会随占空比变化，这也是板上真实会发生的
- 方案 3 载波按 84 kHz 假设，载波本身超出模拟带宽，未模拟载波漏到听觉的分量和电路非线性
- 方案 3 钢琴音：3 ms 起音，8 次谐波、越高衰减越快、轻微非谐性，松键 60 ms 制音；声部满时抢占最早开始的音

## 结论

- 全曲渲染无限幅（`--mix-gain 0.35`）
- 响度（蜂鸣器模型后，相对基线 RMS）：包络 -1.2 dB，琶音 -1.8 dB，PWM-DAC -23.9 dB
- PWM-DAC 的响度损失是主要代价：声部叠加需留余量，且低音区落在谐振峰外；可提高 `--mix-gain` 接受少量限幅、减少声部或整体移高八度
- 用户试听第一轮：1 略优于 0 但有琵琶感；2 兹拉声重，放弃；3 太小声，放弃钢琴合成
- 琵琶感推测来自占空比包络：占空比变小时谐波比例变化，音色随衰减扫动；6 用于验证
- 第二轮响度（相对基线）：4 -0.4 dB，5 +2.1 dB，6 -2.1 dB，7 -5.4 dB，8 -0.4 dB
- 用户试听第二轮：4 琵琶/手风琴感强，5 稍好，6 接近普通单音，7 最好听；7 的问题是旋律休止而伴奏未松开时伴奏显得突然变强；8 起音有嗡声
- 结论：琵琶感来自占空比包络改变音色，干净衰减需 PWM-DAC；方向定为 7 系列
- 7 系列响度：7 -5.4 dB，7b -6.0 dB，7c -5.4 dB，7d -4.8 dB
- 用户试听第三轮：7/7b/7c 区别不大，7d 偏空灵；下一步上板测试不升八度的 2 声部方案
- 最终以板上实测为准

## 上板测试（mc02）

中间测试 app 已归档到本目录 `firmware/`（不再生成 preset，需要时复制回 `app/test/` 并运行 `tools/update_presets.py`）；共用代码在 `firmware/common/`，直接用 HAL 的 `htim12`，不动 lib/bsp

| app | 做法 |
| --- | --- |
| `buzzer_duo_v1` | 首版：Timer 轮询 40 kHz 写 CCR，采样与 80 kHz 载波不同步，各声部 0.5 |
| `buzzer_duo_sync` | 轮询 TIM12 UIF，每载波周期 1 个采样（80 kHz）；PolyBLEP 限带方波；各声部 0.7、旋律余音底 0.45 |
| `buzzer_duo_bias` | sync 基础上动态偏置：占空比中点跟随包络（2 ms 低通），休止时回到 0 |
| `buzzer_diag` | 循环 5 段各 3 s：空载 50%、A4 不同步、A4 同步、C7 未限带、C7 PolyBLEP |

- 曲目：`python -I agents/tasks/02-buzzer_timbre/gen_duo.py` 生成 `app/test/common/always_with_me_duo.hpp`，旋律 991 条、伴奏 856 条
- 第一版反馈：能播放，音量小，有沙沙声且按住蜂鸣器会变小；推测主因是采样与载波不同步的时间抖动，其次是方波混叠
- 编译：四个 preset 均用 CLion 自带 cmake/ninja 构建成功（Debug），app/test 无警告；全局仅 1 条 Eigen `-Walloc-size-larger-than` 警告，与本任务无关
- 烧录：`openocd -f boards/mc02/openocd.cfg -c "program build/<preset>/rmpp.elf verify reset exit"`
- 第二版反馈：sync 改善沙沙声；diag ① 空载无声，③ 优于 ②（抖动），⑤ 优于 ④（混叠）；音量仍不足
- 自动增益：`buzzer_agc_full/3/2`（`common/agc.hpp`），full 响度跳变突兀，3 与 2 差别不大
- `buzzer_probe`：扫频 3–4 kHz 最响（谐振区），偏置与幅度两组符合线性预期，80 kHz 驱动线性，PWM-DAC 可用
- 新问题：低音和复音时沙沙/不干净；推测为低音方波高次谐波大量落入谐振区，两声部高次谐波十二平均律下相差数十 Hz 产生粗糙拍音
- 第四版上板（soft_lp/soft_tri/diag2）：低音方波低通后沙沙声与响度同时消失，说明低音响度就是谐振区内的密集高次谐波；和弦低通更干净，确认粗糙感来自高次谐波拍频；三角波伴奏干净但几乎听不到
- 钢琴波表（谐波比取自用户 github.com/xzqiaochu/piano）模拟 9 系列：9b 远优于 9a 方波，9c Schroeder 相位差别不确定（峰值因数 1.47→1.68，并未提响），9d 亮暗双表的高次衰减很有感觉，9e 方波旋律与 9a 一样难听
- 结论：音色方向定为钢琴波表 + 亮暗双表；待解决响度（约 -9 dB），9f–9i 对比提响手段
- 9f–9i 反馈：9h 软限幅有明显沙沙声（混音后非线性产生互调），放弃；其余差别不大，增益类手段已到上限
- 上板 9f：`buzzer_piano`，`common/piano.hpp` 启动时生成 256 点亮、暗两张波表，线性插值，按 `decay_` 交叉混合
- 提响方向：按蜂鸣器调整频谱（9j–9l），第 h 次谐波乘 min(1, h·f/fc)^p，削弱低于 fc 的基波，靠缺失基波效应保留音高
- `buzzer_piano` 上板：非常干净但音量极小；电脑模拟严重高估非谐振区响度，音量判断只以板上为准
- `buzzer_formant`（钢琴波表上增强最接近 3.5 kHz 的一根谐波）：响度有改善但音色越来越怪，不可接受；方波对照音量可接受但仍略小于单音方波
- 结论：该蜂鸣器响度只取决于 2.5–4.5 kHz 能量，钢琴音色与响度不可兼得；转为旋律方波为主、伴奏点缀
- `buzzer_mix`：6 段对比（单音基准、双声部方波、旋律 0.8/0.9 + 钢琴或方波伴奏、旋律不衰减），旋律休止时自动增益保持
- `buzzer_mix` 反馈：1 单音与原播放器一致（同步采样 + PolyBLEP 无损耗）；2 双声部 0.5/0.5 响度约减半、伴奏可闻但有拍频；3–6 响度相近且明显大于 2，钢琴伴奏 0.1–0.2 几乎听不到，方波伴奏 0.2 略可闻
- 结论：钢琴波表伴奏在该蜂鸣器上无效；方向为方波旋律为主 + 方波伴奏，细调伴奏权重
- `buzzer_mix2`：从曲目 20 s 起（之前伴奏少），对比方波伴奏 0.2/0.3/0.35、2 kHz 低通、余音底 0.3
- `buzzer_mix2` 反馈：伴奏 0.3 比 0.2 清晰且音量损失不大；0.35 略清晰但损失更多；2 kHz 低通更干净但伴奏几乎消失；伴奏余音底 0.3 拖沓

## 最终方案

- `app/test/buzzer_duo/`（preset `test-buzzer_duo`）：旋律方波 0.7（tau 0.7 s、余音底 0.6）+ 伴奏方波 0.3（tau 0.4 s、余音底 0.12），不低通；自动增益压缩比 4、下降 5 ms、上升 150 ms，旋律休止时保持
- 单文件实现，去掉了中间版的波形枚举、低通、钢琴表、共振峰与分段播放
