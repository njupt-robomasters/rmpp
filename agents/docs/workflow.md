# 协作、验证与约定维护

开始修改前读取，构建细节另见 build.md、verification.md。

## 协作

### 并行修改

- 默认用户、多个 AI 和其他工具可能同时修改工作区；非本任务产生的改动都视为他人工作，必须保留
- 开始前检查 Git 状态和相关 diff，区分已提交、暂存、未暂存修改
- 编辑前重新读取目标文件；外部变化时基于最新内容合并，不用旧内容整文件覆盖
- 修改重叠且无法安全合并时，停止并说明冲突

### 修改边界

- 只编辑当前任务涉及的文件和代码段，不顺手整理、格式化或修复无关内容
- 不擅自回滚、删除、暂存或提交他人修改，不用恢复命令清理工作区
- 命令限定到职责范围，避免改写无关文件
- 在当前分支和工作区工作；用户明确要求时才新建分支或 worktree，合并后随即删除
- 无关错误只报告，不擅自扩大任务范围
- `.ioc` 与 CubeMX 生成文件（含 USER CODE 区）由用户操作；AI 给出页面、参数、勾选项和 USER CODE 片段，并核对生成结果

### 推进

- 用户明确要求开始改代码前，只做分析和规划：可读代码、查资料、更新 `agents/TODO.md` 与约定文档，不修改工程代码、配置和目录
- 用户要求开始后，已确认的需求直接推进，不重复确认
- 只有缺失信息会改变实现或无法安全继续时才提问
- 改名、删除接口、移动文件时，同步迁移职责范围内的调用点、依赖和文档；跨出职责范围先说明影响
- 用户要求保留基线时，修改前记录可复核的 Git 基线

## 验证与交付

### 验证

- 验证与改动相称，区分格式检查、局部编译、完整目标构建、测试、硬件验证
- 代码修改完成格式检查、职责范围内的真实编译和必要测试，确保负责部分编译成功
- 默认不执行全量构建，用户特别要求时才执行；存在其他 AI 并行修改时只编译本次涉及的文件
- 纯文档修改只检查内容、格式和 diff
- AI 自写测试程序放在对应 `agents/tasks/NN-名称/`
- 示例和测试程序把观察量放在全局对象或 `static` 变量，由用户用 SWD 看变量波形；用户要求时才加 CDC 打印
- 调试器只读观察可直接进行；烧录、复位、halt、改写内存或寄存器前先说明操作并经用户同意。用户单板测试常不接电源，板子在机器人上时擅自操作可能使机构误动作
- 只对实际取得最终结果的范围报告成功；无关修改导致的失败保留现场并准确报告

### 交付

- 交付前重新打开实际工作区文件，搜索旧名称和残留，检查最终 diff
- 不只凭暂存 diff 或先前构建结果宣称完成
- 先报告结果，再简述变化、验证和限制
- 涉及删减时说明原用途和删除影响
- 完整构建报告错误、警告和产物
- 回答和文档使用中文
- 用户人工审计后决定是否上车测试

## 约定维护

### 触发与归属

- 留意用户明确提出的新规则和对旧规则的修正，稳定、可复用的在当前任务内落盘
- 推测的偏好、一次性决定和偶然实现先确认，不自动上升为规则
- 通用编码规则写入 conventions.md，协作与验证规则写入 workflow.md；AGENTS.md 只保留必要入口
- 仅特定模块适用的规则写入 `agents/docs/` 对应文档，并同步“文档读取”索引
- 对用户需求的理解、AI 工作区说明和任务索引写入 `agents/README.md`
- 根目录 `README.md` 面向人，只写简短上手指南和目录作用，不写 AI 工作内容
- 具体接口说明、临时待办、硬件配置和验证结论不写入本文件

### 整理方式

- 更新前读取现有条目，修改原规则，不在末尾重复追加
- 合并重复内容，删除冲突、失效和已迁移条目
- 保持短句、小标题和单一职责，避免规则膨胀
- 规则与已核对代码冲突时，以用户确认的意图为准；不把未核对实现或偶然缺陷固化为约定
- 交付前判断是否产生新的稳定约定；没有则不做形式化改动
